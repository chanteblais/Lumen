### CURRENT CANON

I grounded this run in the connected Drive package, beginning with **COHERENCE_START_HERE**, then **COHERENCE_CURRENT_STATE**, **COHERENCE_DESIGN_CANON**, **COHERENCE_OPEN_QUESTIONS**, and **COHERENCE_RECENT_CHANGES**. I also checked the current **Coherence — Today / Garden** design document because this question touches the distinction between enduring importance and Today’s temporary foreground.

One distinction is already firmly settled: **importance, urgency, user-expressed priority, and present-attention relevance are not the same thing**. Today is allowed to recommend something other than the user’s most important overall concern because deadlines, capacity, sequencing, available time, or dependencies can temporarily change what makes sense now.

Likewise, a Today-specific correction must not quietly rewrite the user’s broader priorities. “I don’t want to touch school today” does not mean school stopped mattering. And a single rearrangement is contextual evidence, not a new permanent rule.

### DIRECTION

Coherence should become unusually good at remembering **what the user has actually said matters**, while still being intelligent enough not to turn those statements into rigid sorting rules.

That means explicit priority needs more durable representation than “whatever the ranking model currently thinks,” but less rigidity than a universal priority field attached to every task.

### OPEN QUESTION

**Q11 — How should stated priorities persist?**

The unresolved part is what happens after someone says things like:

> “Practicum is my main priority this semester.”

> “For the next two weeks I really need to focus on taxes.”

> “My health comes before work.”

> “I want Coherence to be my main project right now.”

Some of these are temporary. Some are broad. Some are about a specific Thread. Some sound enduring but may later change.

If Coherence simply converts them into hidden numerical weights, it loses meaning and scope. If it stores them forever as absolute rules, yesterday’s self can start governing today long after circumstances change.

### PROPOSAL — **Priority declarations, not priority scores**

I’d make an explicit user priority a small first-class piece of context: a **priority declaration**.

The important thing being preserved is not a number such as `priority = 8`. It is the meaning of the statement:

> **Practicum comes first this semester.**

Internally, that declaration would carry a few semantic boundaries: **what it applies to, how broad it is, what time horizon was expressed, and what later statement supersedes it**.

The system does not need to expose those fields as a form.

If the user says:

> “Taxes are my priority until the end of the month.”

Coherence can understand that as a scoped, time-bounded declaration. When the month ends, it stops governing present recommendations automatically. It remains useful history, but it is no longer current instruction.

If they say:

> “My relationships matter more to me than work.”

there is no obvious expiry. Coherence should therefore retain that as an open-ended value-level priority rather than inventing one.

The conservative parsing rule should be:

> **Never make a priority broader or more permanent than the user’s language supports.**

So “I need to focus on school today” is a today-level instruction.

“I’m focusing on school this term” is longer-lived.

“School is the most important thing in my life” is genuinely broad.

That keeps Lumi from accidentally converting momentary frustration or enthusiasm into identity.

The second important rule is that **priority declarations influence recommendations; they do not mechanically determine them**.

Suppose the user has told Lumi:

> “The paper matters more than anything else this week.”

But today their insurance expires.

Lumi should be able to recommend the insurance call first while retaining the paper’s higher enduring importance:

> “The paper is still the bigger priority. I’d do the insurance call first because it expires today.”

Nothing about that interaction changes the paper’s stored priority.

This cleanly separates:

**What matters more overall** from **what makes sense to attend to now**.

That separation is one of the places where Coherence can be substantially smarter than conventional task apps.

### Supersession should be surgical

If the user later says:

> “Actually, practicum isn’t my main priority anymore. Finishing school is, but I want Coherence to take most of my free time.”

Coherence should not simply delete the earlier belief and replace it with one giant new ranking.

It can preserve the evolution:

**Practicum first this semester** → superseded as a broad priority.

**Finish school** → current broader priority.

**Coherence gets most discretionary time** → current scoped attention preference.

That history gives Lumi useful context without presenting old statements as current truth.

It also allows subtle distinctions that a numeric ranking cannot express. Something can be deeply important while intentionally receiving little time right now.

### Priority can become stale without becoming false

There is one edge I think matters a lot.

An open-ended explicit priority should not silently “decay” into being unimportant merely because months pass. That would let system inference override user authority.

But old declarations can become **review-worthy** when the world around them changes.

If the user once said:

> “Getting this promotion is my main goal.”

and six months later they are discussing leaving the company, Lumi can notice the contradiction:

> “You’d told me the promotion was a major priority, but it sounds like that may not be true anymore.”

That is not the system deciding the priority expired.

It is the system noticing that the user may want to supersede it.

This connects directly to the earlier **memory receipts** exploration: if a recommendation is materially influenced by an old priority statement, the user should be able to inspect the provenance and correct it there.

### What this gives Today

Today gets much stronger reasoning without adding UI.

It can understand:

> “This matters enormously, but not today.”

> “This is not especially important overall, but it has to happen before 4.”

> “You told me writing is what you most want to protect this month, so I’m not filling the whole morning with easy administrative work.”

> “You said you wanted a very light day today, so I’m treating that as a temporary instruction rather than changing your broader priorities.”

That is exactly the kind of **qualitative judgment** the Garden documents are aiming at.

The user does not need to maintain a priority matrix. Lumi carries the distinction.

### HISTORICAL / REJECTED BOUNDARY

I would explicitly avoid a universal `Low / Medium / High` system, 1–5 stars, Eisenhower quadrants, hidden scalar “importance” scores presented as truth, or requiring users to rank every List.

Those approaches flatten several different questions into one:

**How much do I care about this?**  
**How urgent is it?**  
**Does it deserve attention today?**  
**Am I willing to spend capacity on it now?**

Coherence is specifically interesting because it does **not** have to pretend those are identical.

The principle I’d add to the canon is:

> **Remember priority as a scoped statement of meaning. Compute attention from the present situation. Do not confuse one for the other.**

I don’t think a mockup would improve this exploration. The useful design work is in the shared-model semantics and Lumi’s behaviour; the best UI consequence is probably that almost none of this machinery needs to become visible unless a priority is influencing a consequential recommendation or the user wants to correct it.
