### CURRENT CANON

Today is already designed around **stable orientation rather than live optimization**. It persists one Right now item, a short After that path, and fixed-time Later commitments; it does not continuously reshuffle itself as time passes. The current implementation only changes the plan on documented triggers such as a new day, capacity change, decline, re-entry, or explicit conversational reshaping. The broader direction is that Today may adapt when life actually changes, but without undermining the user’s trust in what they saw five minutes ago.

That matters alongside two other settled constraints: inactivity does **not** imply failure, and returning after an absence should reconstruct the present rather than confront the user with accumulated debt.

### OPEN QUESTION

Q26 leaves one important boundary unresolved:

**When should Today decide that the plan it showed earlier is no longer the right representation of the day?**

A continuously adaptive system would be “smart,” but psychologically expensive: if Today can reorder itself whenever new evidence arrives, the user has to keep rescanning it.

A completely frozen system has the opposite problem. By 4 p.m., the morning’s sensible plan may simply be false.

### PROPOSAL — **Re-entry is the adaptation boundary**

I’d make Today’s default rule:

> **The plan stays yours until you come back to it.**

Coherence can notice changes in the background, but it should normally wait for a **natural re-entry moment** before reconsidering the visible path.

Re-entry could mean opening Today after spending meaningful time elsewhere, returning from Study, or coming back after the app has been closed. It should *not* mean “you were inactive for 47 minutes, therefore something went wrong.”

At that boundary, Coherence performs a quiet **validity check**, not a fresh ranking.

The question is simply:

> **Does the existing path still make sense from here?**

Most of the time, the answer should be yes, and nothing happens.

If something materially invalidated the plan—perhaps a fixed-time commitment has passed, the user explicitly changed capacity, a priority was superseded in conversation, or they completed substantial work somewhere else—Today could preserve the current page and introduce one small piece of orientation:

> **The day moved a little.**  
> I can keep this path, or reshape it around now.

**Keep this path**  
**Reshape from here**

No modal. No mandatory review. No automatic cascade of cards.

And I would draw a hard distinction between **mechanical invalidation** and **interpretive invalidation**.

A 2 p.m. appointment that is now in the past can quietly stop appearing as an upcoming landmark. That is factual.

A task sitting untouched since 10 a.m. does **not** automatically become a bad recommendation. That would require interpreting absence as resistance, which the canon explicitly rejects.

The same rule helps with the Study proposal from the previous exploration. While the user is in Study, Today should effectively **hold still**. When they return, Coherence can incorporate what happened during the work session—if anything is actually known—before deciding whether the remaining path needs adjustment.

This creates a clean temporal model:

**Plan → live with the day → re-enter → check validity → preserve or reshape**

rather than:

**Plan → algorithm continually recalculates → user discovers a different day whenever they look**

I’d also make **Reshape from here** fundamentally forward-looking. It should not ask the user to account for the hours that disappeared. It starts with *now*: current capacity, remaining commitments, anything completed or changed, and what still matters.

That gives Today an important promise:

> **I won’t move the ground under you. But when you come back, I can help the map catch up.**

I wouldn’t mock this one up yet. The key decision is behavioural, and the existing Today composition already has the right visual hierarchy. If this rule is adopted, the eventual UI addition should be extremely small—a transient re-entry cue, not a new planning surface.
