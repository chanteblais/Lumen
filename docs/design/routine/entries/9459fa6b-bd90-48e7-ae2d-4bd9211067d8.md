## CURRENT CANON

Focus Together currently runs on Home as a single session with a goal, first step, planned duration, check-ins, and session-end reflection. There is also a known implementation mismatch: if an open session survives past roughly twice its planned duration, the system can sweep it into an **abandoned** state, and that abandonment can become negative evidence about the strategy. The canon explicitly rejects that inference. Leaving, inactivity, or simply failing to report back does not tell Coherence whether the user failed, finished elsewhere, got absorbed in the work, intentionally stopped, or just forgot the app was open. fileciteturn8file1L18-L18

The previous Focus exploration also established a useful boundary I would preserve here: **the planned end of accompaniment is not the same thing as a verdict on the work**.

## DIRECTION

I think session learning needs two separate questions:

> **What happened with the work?**

and

> **Was this form of support useful?**

Those are currently too easy to collapse together.

Someone might spend 45 minutes on a genuinely difficult task, make little visible progress, and find Lumi’s presence extremely helpful.

Someone else might finish the task completely but discover that body doubling was distracting.

And someone may close Coherence halfway through because they finally got momentum and no longer needed it.

If all three become a single implicit **session outcome**, Coherence will learn the wrong things.

## OPEN QUESTION

This is **Q28 — What can a session ending tell us?**

The settled part is already strong: **unknown ending, explicit abandonment, and useful work outside the app must be distinguishable**, and inactivity alone cannot count as strategy failure.

The unresolved design question is:

> **What should Coherence actually retain from a Focus Together session so that it can learn over time without turning the end of every session into a performance review?**

## PROPOSAL — **Separate the work trace from the support trace**

I would model a Focus Together session as leaving two independent traces.

The first is a **work trace**:

> What do we actually know happened to the thing the user was working on?

The second is a **support trace**:

> What do we actually know about whether this particular kind of accompaniment helped?

Both are allowed to remain **unknown**.

That last part is essential.

### The work trace should only say what there is evidence for

Possible internal outcomes might eventually include:

- **Completed**
- **Made progress**
- **Paused intentionally**
- **Didn’t really get started**
- **Changed direction**
- **Unknown**

But Coherence should not require the user to choose one every time.

It can know **Completed** when the user presses Done or later says they finished it.

It can know **Made progress** when they explicitly say so.

It can know **Changed direction** if the session turns into a different next step and the user adopts that.

If the timer expires and the app hears nothing else:

> **Unknown.**

If the browser closes:

> **Unknown.**

If three hours pass:

> **Still unknown.**

That technical restraint is important because it prevents Coherence from turning absence into psychology.

### The support trace should be even more conservative

The session outcome should not automatically become evidence about whether body doubling works for this person.

The only strong evidence should be things like:

> “That really helped.”

> “The check-ins were distracting.”

> “Can we do this again tomorrow?”

> “Don’t do the timer thing next time.”

Those are actual statements about the support strategy.

Finishing the task is **not automatically positive strategy evidence**.

Failing to finish is **not automatically negative strategy evidence**.

Even “Got distracted” during a check-in does not prove the session format is bad; the intervention may be exactly what helped the user return.

So the support trace could remain simply:

**Helpful / Unhelpful / Mixed / Unknown**

with **Unknown** being extremely common.

That is fine. Coherence does not need to optimize from every interaction.

## The end-of-time interaction can stay very small

When the planned duration arrives, I would keep the transition from the previous Focus proposal:

> **That’s the time you set aside.**

with something like:

**Keep going** · **Wrap here** · **Done**

That is about what happens **next**, not scoring what just happened.

If the user chooses **Done**, the work trace is clear.

If they choose **Keep going**, the session continues.

If they choose **Wrap here**, Coherence can preserve the current position without assuming why they stopped.

The session does not need to immediately ask:

> “How productive were you?”

or:

> “Did body doubling help?”

That turns an ending into paperwork.

### Reflection should be opportunistic rather than compulsory

There are moments when learning would actually be useful.

Suppose the user finishes and says:

> “Wow, that worked way better than trying to do it alone.”

Lumi already has the support signal. No follow-up form is necessary.

Or suppose they say:

> “The check-ins were kind of annoying.”

Again, that is high-quality evidence.

Only when there is a genuinely useful ambiguity might Lumi occasionally ask something light:

> “Was having me here useful, or did you mostly find your own momentum?”

That asks about **support fit**, not whether the user succeeded.

And I would not ask it after every session. Repetition would quickly turn Focus Together into a self-tracking protocol.

## Returning after an unresolved session should reconstruct, not judge

This is where the current abandoned-session mismatch should change most clearly.

Suppose the user starts:

> Finish practicum case notes

and disappears 23 minutes into a 45-minute session.

They return two days later.

Coherence should not greet them with:

> “You abandoned your focus session.”

Nor should it silently record body doubling as ineffective.

The useful retained information is simply:

> You were working on the case notes.  
> The last known step was drafting the assessment section.  
> We don’t know what happened after that.

If that context becomes relevant, Lumi might say:

> “Last time we were together, you’d started the assessment section. Did you end up getting anywhere with it?”

And if the user says:

> “Oh yeah, I finished the whole thing after I closed the laptop.”

Coherence can reconcile the work trace **after the fact**.

That is exactly the kind of re-entry behaviour the wider product philosophy calls for: reconstruct reality instead of preserving a stale system verdict.

## Technical session state should not leak into semantic outcome

I would make a strong implementation distinction here.

A session may technically need states like:

**active → expired → closed**

for cleanup and UI purposes.

Those states should **not** mean:

**working → failed → abandoned**

The database needing to close a stale session is an administrative fact.

It is not knowledge about the user.

So if an old active session has to be swept, the semantic outcome should become:

> **Ended, outcome unknown**

rather than:

> **Abandoned**

unless the user actually abandoned it.

That one change would eliminate a whole class of bad downstream inference.

## This also creates better long-term learning

Over time, Coherence can learn useful things from **explicit patterns in support fit**:

> quiet presence tends to help with writing;

> frequent check-ins are useful for administrative tasks but irritating during creative work;

> a 20-minute beginning threshold often helps the user get started, after which they prefer Lumi to disappear.

Those are potentially valuable.

But they should emerge from actual evidence about the accompaniment—not from correlations such as:

> session ended before timer → strategy failed.

This fits the broader model beautifully because the evidence itself can retain provenance:

> **Explicit:** “Check-ins distract me when I’m writing.”

versus

> **Observed:** three writing sessions were continued after the planned end.

The second may inform curiosity. It should not overwrite the first.

## HISTORICAL / REJECTED

I would reject the current semantic use of **abandoned** for sessions that merely time out.

I would also reject:

- completion percentage as the default session outcome;
- treating finishing as evidence that the support strategy worked;
- treating unfinished work as evidence that it failed;
- requiring a post-session questionnaire;
- interpreting closing Coherence as disengagement;
- learning personality-level conclusions from a few session endings.

The canon-level principle I would propose is:

> **A session ending records only what is actually known. Work outcome and support usefulness are separate signals, and either may remain unknown. Technical timeout is not behavioural evidence.**
