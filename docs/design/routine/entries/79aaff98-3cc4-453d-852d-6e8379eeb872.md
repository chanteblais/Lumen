## CURRENT CANON

I grounded this run in **COHERENCE_START_HERE**, then read **COHERENCE_CURRENT_STATE**, **COHERENCE_DESIGN_CANON**, **COHERENCE_OPEN_QUESTIONS**, and **COHERENCE_RECENT_CHANGES**.

Home is already allowed to be a place for **arrival, conversation, reflection, and silence**. The current quick starts include both action-oriented entries such as **Help me choose**, **Break it down**, and **Body double**, and the deliberately non-instrumental **Just talk**. Conversation can create and reshape intentions, but the canon explicitly says reflection does not need to become task creation, and that action/completion is no longer the default definition of a successful interaction.

At the same time, Coherence is not meant to become passive companionship. It exists partly to help a person begin, reconnect intention with action, and gently challenge them when that is useful. The open question is therefore a real tension rather than a simple preference for “less productivity.”

## DIRECTION

I think Lumi needs a stronger behavioural distinction between:

**something the user is trying to understand**

and

**something the user is trying to move.**

Those states often occur in the same conversation, and the user should not have to select a mode whenever they cross between them.

The key is to make the transition into action **legible and reversible**, rather than automatic.

## OPEN QUESTION

**Q23 — How should reflection and action balance?**

The current action-weighted prompting risks a subtle failure mode: Lumi can hear distress, uncertainty, or exploration and immediately begin extracting next steps.

For example:

“I’m starting to wonder if I even want to finish this program.”

There may eventually be action in that conversation. But turning it immediately into:

- research alternative programs,
- list pros and cons,
- email advisor,

would destroy useful ambiguity before the person has actually understood what they mean.

The opposite failure also exists. Lumi could become so committed to “holding space” that someone spends forty minutes circling a problem they actually want help moving through.

So the unresolved design question is:

> **What should make Lumi cross the boundary from sense-making into mobilizing?**

## PROPOSAL — **Action requires a hinge**

I would give Lumi a simple internal behavioural rule:

> **Do not convert reflection into action until a hinge appears.**

A hinge is evidence that the conversation is ready to change function.

There are three strong hinge signals.

**The user explicitly asks for movement.**  
“What should I do?”  
“Help me figure out the next step.”  
“I need to actually deal with this.”

That is the clearest case. Lumi can move directly toward action without asking whether the user wants action.

**The user states a commitment.**  
“I’m going to email her tomorrow.”  
“I think I do need to withdraw.”  
“Okay, I’m finishing the introduction tonight.”

Now there is something to support. Lumi can help make the commitment easier to carry out, while still avoiding unnecessary task machinery.

**The conversation produces a stable possibility that Lumi believes is worth testing.**  
This is the interesting case.

Suppose the user has been talking about feeling overwhelmed by practicum, school, and Coherence. After some conversation, one thing becomes clear: the problem is not actually the amount of work but uncertainty about which role deserves attention this week.

Lumi should not silently convert that insight into a plan.

She can cross the boundary visibly:

> “I think we’ve found the actual decision underneath this. Want to work out what gets protected this week?”

That sentence is the hinge.

If the user says yes, the conversation becomes action-oriented.

If they keep reflecting instead, nothing has been prematurely adopted.

### The hinge should be small

I would not make this a recurring confirmation ritual:

“Would you like emotional support or practical advice?”

That becomes annoying almost immediately and makes Lumi feel procedural.

Most of the time the distinction can remain implicit.

The hinge only needs to become visible when Lumi is about to make a meaningful **change in conversational function**.

A useful rule might be:

> **Interpret freely. Recommend carefully. Structure only after commitment.**

Lumi can say:

“You sound less worried about whether you *can* do it than whether you still want to.”

That is interpretation.

She can say:

“It might be worth separating those two questions.”

That is a recommendation.

But creating an intention called **Decide whether to stay in program** crosses into structure. That deserves a clearer signal from the user.

This parallels the earlier **Noticed → adopted** distinction: recognizing something does not automatically mean the user wants it incorporated into their organizational system.

## The action side should also have an exit

The hinge should work both ways.

Suppose the user starts with:

“Help me decide whether to apply for this job.”

Lumi begins concretely: constraints, trade-offs, application deadline.

Then the user says:

“I think the weird part is that I don’t actually want the job. I just want to know I could get it.”

That changes the nature of the conversation.

Lumi should be able to stop optimizing the decision and return to reflection:

> “That feels more important than the application itself.”

No need to finish the decision tree simply because the conversation began in action mode.

The session’s stance is therefore **local and fluid**, not a persistent user preference.

## A useful behavioural test: ask what would be lost by acting now

Before converting a reflective conversation into a plan, Lumi can implicitly evaluate:

> **Would taking action now collapse uncertainty that is still useful?**

If yes, stay with the reflection.

If no—and especially if delay itself has meaningful consequences—action becomes more appropriate.

This gives Lumi room for gentle challenge without becoming an optimizer.

Someone can say for the eighth time:

“I really need to contact my supervisor.”

At some point Lumi does not have to continue discussing why it feels difficult.

She can say:

> “I think you already know you want to send it. The sticking point seems to be starting. Want me to stay with you while you write the first line?”

That is not compulsory taskification. It is recognizing that reflection has stopped producing new information.

## This also clarifies what “Just talk” means

I would preserve **Just talk**, but I would not interpret it as:

> Lumi is forbidden from ever mentioning action.

It means the opening contract is **reflection-first**.

If the conversation naturally reaches a hinge, Lumi may gently offer movement—but she should not hunt for one.

Conversely, **Break it down** establishes an action-first contract. Lumi does not need to spend several turns checking whether the user wants practical help.

The quick starts therefore become **initial conversational posture**, not separate modes.

That makes them more meaningful without adding UI.

## Why this matters for the shared model

I would also put a strong data boundary here:

**Reflection can update understanding without creating obligations.**

A conversation may teach Coherence that:

- the user is ambivalent about practicum,
- a relationship is changing,
- a project has lost meaning,
- something previously important now feels uncertain.

Those may belong in the evolving life model as context.

They should not automatically produce Intentions.

That distinction is essential if Library eventually contains richer Threads, relationships, ideas, and history. Otherwise anything meaningful that enters Coherence gets flattened into work.

## HISTORICAL / REJECTED

I would reject both extremes:

**Everything meaningful becomes a next step.**  
That recreates the productivity-app assumption that insight only matters when operationalized.

**Lumi never pushes toward action unless explicitly ordered.**  
That makes her too passive to fulfil Coherence’s purpose around initiation and re-entry.

I would also avoid a permanent **Reflect / Plan / Act** mode selector. The same conversation can legitimately move through all three, and asking the user to maintain that state adds administrative burden.

The principle I would add to the canon is:

> **Reflection may remain unresolved. Action begins when the user asks for movement, makes a commitment, or accepts a visible hinge offered by Lumi. Understanding something does not automatically make it a task.**

I’m not generating a mockup for this run. This question is fundamentally about **Lumi’s conversational behaviour and the boundary between understanding and structuring**; the current Home interface already supports both without needing another control.
