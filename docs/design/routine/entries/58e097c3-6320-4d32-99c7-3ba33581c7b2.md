### CURRENT CANON

I grounded this run in the Drive package: **COHERENCE_START_HERE**, **CURRENT_STATE**, **DESIGN_CANON**, **OPEN_QUESTIONS**, and **RECENT_CHANGES**, and I inspected the actual current **03-today-garden** capture.

Today currently has a deliberately narrow hierarchy: one dominant **Right now** item, followed by a quieter **After that** path, with fixed-time commitments separated as **Later**. The plan is supposed to remain stable enough to trust rather than constantly re-optimizing itself.

Direct manipulation is allowed in principle, but one rearrangement must not silently become a permanent preference. **Not today** is also explicitly different from moving something to another list, scheduling it tomorrow, or reducing its importance.

### DIRECTION

The user should be able to correct Coherence directly when that is easier than explaining the correction in conversation.

But the interaction needs to preserve **scope**. Moving something because *this afternoon changed* should not teach Lumi that the item is generally less important.

### OPEN QUESTION

Q20 asks how direct manipulation should express that scope: what Today reordering means, whether it affects durable organization, what Lumi learns from it, how undo works, and what the equivalent non-drag interaction is.

The current Today screen makes this especially relevant. **After that** visually reads like a path, but at present it is largely something Coherence presents rather than something the user can casually shape.

### PROPOSAL — **Let me adjust the path, not the underlying priorities**

I’d make **After that reorderable within Today**, with a deliberately narrow semantic contract:

> Dragging changes the sequence of *today’s visible path*. Nothing more.

If the user moves:

**Reply to Richard**  
above  
**Pick up prescription**

Coherence records something like:

**Today-path correction: Reply to Richard before Pick up prescription**

—not:

**Reply to Richard has higher global priority.**

That distinction should exist in the data/model, not just in explanatory copy.

I would keep **Right now** slightly more protected. Dragging an After that item into the Right now position should not silently swap it. Crossing that boundary means something stronger: *I want to change what I’m attending to now.*

So when the user drags an item upward into that region, the card could pause at a clear threshold and offer:

**Make this Right now**

Confirming would reshape Today around that item and demote the previous Right now item back into the path without implying rejection or reduced importance.

This gives the page two distinct gestures:

**Reorder within After that** → “This sequence suits today better.”  
**Move into Right now** → “I want to change focus now.”

I would **not** let Today dragging move items into **Later**, because Later currently means fixed-time landmarks rather than generic postponement. Visually it may be lower on the page, but semantically it is not simply the bottom of the task list. That is exactly the kind of interface shortcut that would eventually muddle Coherence’s vocabulary.

There should also be a non-drag equivalent, especially for mobile and accessibility. Opening an After that item could offer restrained controls such as **Move earlier**, **Move later**, and **Make Right now**. These should invoke the exact same scoped operations as dragging.

After a rearrangement, I’d use the existing quiet ledger language rather than a modal:

> **Today reshaped.**

And briefly expose **Undo** beside it.

Lumi can learn from repeated corrections, but only cautiously. If someone moves writing work earlier five times across several weeks, that may eventually become evidence worth discussing or considering. One drag on one strange Tuesday should remain exactly what it was: a local correction.

That gives direct manipulation a principle I think is worth making explicit in the canon:

> **The visible thing you moved defines the default scope of the move.**

Move something inside Today → you changed Today.  
Move something inside an eventual Library collection → you changed that organization.  
Tell Lumi “this matters more to me in general” → that is when durable priority changes.

This would make the Garden feel more responsive without turning it into a manual planning board or forcing users to explain every small preference conversationally.

### HISTORICAL / REJECTED BOUNDARY

I would not revive freeform spatial task placement in the painted garden or make users physically “plant” tasks to organize them. The current room should remain visually rich and operationally restrained. The direct manipulation belongs in the existing paper path, where its meaning can stay clear.

I’m not adding a mockup on this run because the actual current Today capture already gives enough visual grounding, and the consequential decision is the **scope semantics** behind movement. The UI change itself can stay very small once those semantics are settled.
