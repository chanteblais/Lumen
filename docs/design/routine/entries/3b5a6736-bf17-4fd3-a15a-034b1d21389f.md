It asks capacity once per day, persists its path across reloads, and only reshapes on specific triggers such as explicit capacity changes, **Not this**, re-entry, or conversational replanning. The garden screenshot reinforces that stability visually: the page is mostly environment, with a single strong parchment card and a much quieter remainder rather than a live dashboard. fileciteturn11file0L1-L9

That stability is not accidental. The design canon says omission should be trustworthy and the user should not have to keep mentally checking whether the system has changed its mind.

## DIRECTION

Today should be able to respond when the day genuinely changes, but **time passing alone should not cause the plan to churn**.

I’d make the governing principle:

> **Hold the path steady until reality materially invalidates it. Then explain the change before reshaping it.**

That fits the earlier work on scoped priority: a temporary change in circumstances can alter what deserves attention now without rewriting what matters more broadly.

## OPEN QUESTION

This is **Q26 — When should Today adapt during the day?** The open question explicitly asks how stable orientation and meaningful adaptation coexist, and when a change needs explanation. fileciteturn12file0L1-L9

The failure modes on either side are pretty clear.

If Today continuously re-ranks itself, it becomes untrustworthy. The user returns at 3 p.m. and the thing they had mentally oriented around has vanished because the algorithm decided something else was more efficient.

But if Today never notices that the morning plan has become impossible, it stops being a useful representation of the present.

## PROPOSAL — **Re-entry checkpoints, not continuous recuration**

I would make Today adapt at **meaningful re-entry moments**, rather than running a background ranking loop.

A re-entry checkpoint happens when the user comes back to Today and something significant has changed since the current path was formed.

Most returns should do absolutely nothing.

If the plan is still viable, the page should simply remain the page the user remembers. No “review your day” ritual. No recalculation animation. No new prompt.

The system should only intervene when it detects a **material mismatch** between the existing path and the present.

Examples:

- the user explicitly said their capacity dropped;
- a fixed-time commitment is now close enough that the existing sequence no longer fits;
- the user told Lumi a priority changed;
- something in the path was completed outside Coherence and that is known;
- the user returns after a long gap and the previous Right now is no longer possible in its original form.

Importantly, these are changes in **known reality**, not behavioural interpretations.

> “You haven’t touched this for four hours” is **not** a material mismatch.

Inactivity still tells Coherence almost nothing.

### When nothing important changed

Today stays exactly where it was.

That consistency is itself useful feedback:

> I can trust that this still represents what we decided.

Lumi does not need to announce:

> “Your plan is unchanged!”

Silence is better.

### When something changed, but the existing path still works

Again, I would usually leave the page alone.

Suppose an appointment was moved from 4:00 to 4:30 but the current path still fits.

Coherence knows the update. It does not need to make the user process the update twice.

This is the “show less than you know” principle applied temporally.

### When the path genuinely no longer fits

This is where I would add one small interaction to the existing Today composition.

Not another panel.

Not a refreshed task list.

A temporary, quiet **re-entry slip** immediately above the current Right now card:

> **The day shifted a little.**  
> Your 2:00 appointment is close now, and you said you have less energy than this morning.  
> **Keep this path** · **Reshape with Lumi**

The current Right now remains visible underneath.

That matters because Coherence is not silently replacing the user’s orientation and then asking them to accept the result after the fact.

They can see:

**what was true**  
and  
**why Lumi thinks it may no longer fit.**

If they choose **Keep this path**, the slip disappears.

That choice should not become a permanent preference like “user dislikes replanning.” It only means the previous path still feels right **now**.

If they choose **Reshape with Lumi**, the normal conversational replanning mechanism can do what it already does: negotiate attention, then update the actual Today path.

This extends existing behaviour instead of creating a parallel planner.

## Some changes should remain automatic

I would distinguish **state maintenance** from **attention decisions**.

Coherence should not ask permission to perform obvious housekeeping.

If the user marks Right now **Done**, advancing the existing path is already expected.

If a 2 p.m. calendar landmark is now in the past, it should no longer visually present itself as an upcoming 2 p.m. landmark.

If the user explicitly tells Lumi:

> “I’m wiped. Make today smaller.”

Today can reshape immediately, because the user already authorized the operation.

The re-entry checkpoint is specifically for cases where **Coherence has detected a consequential contextual change but the user has not yet told it what that should mean for their attention**.

That boundary keeps the system from becoming either inert or paternalistic.

## The trigger should be significance, not elapsed time

I would resist rules like:

> Replan every three hours.

or:

> Recalculate whenever Today opens.

The user could open Today five times in an hour. Nothing meaningful happened just because the page loaded.

Instead, Coherence could hold a small set of **re-entry reasons** internally:

**Capacity changed**  
**Priority changed**  
**Commitment changed**  
**Current item became impossible / obsolete**  
**Known progress changed the remaining path**

Only if one of those changes would materially alter the recommendation should the re-entry slip appear.

This also gives the system a very useful debugging property: every unsolicited reshaping proposal has a legible reason.

## A useful asymmetry: make Today harder to change than chat context

Lumi can learn many things during the day without constantly projecting them into Today.

That asymmetry is healthy.

Home can know:

> “She is stressed about taxes.”

Library can know:

> “Taxes are an active concern.”

Lumi can know:

> “Energy is lower this afternoon.”

None of those facts individually require Today to change.

Today should have a relatively high threshold because it represents the **trusted foreground**.

That makes appearing there meaningful.

## The re-entry language should describe reality, not judgement

I would avoid:

> “You’re behind.”

> “You haven’t made enough progress.”

> “There isn’t enough time left.”

Even when mathematically defensible, those phrases create unnecessary interpretation.

Better:

> “Your appointment is in 40 minutes, so the current first step may no longer fit before you leave.”

or:

> “You told me your energy dropped quite a bit. This morning’s plan was built for a normal-ish day.”

Concrete, corrigible, and non-moral.

The user can answer:

> “No, I’m fine. Keep it.”

And Coherence moves on.

## This makes re-entry part of the product philosophy

There is a deeper reason I like this.

Most productivity systems treat returning as an opportunity to **recalculate everything**.

Coherence can treat returning as an opportunity to **restore orientation first**.

The sequence becomes:

> Here is where we left things.  
> Has reality changed enough that this no longer serves you?  
> Only then reshape.

That is much closer to how a good human collaborator behaves.

## HISTORICAL / REJECTED

I would reject:

- continuous background reranking of Today;
- automatically replacing Right now because a “better” task scored higher;
- elapsed-time-only replanning;
- interpreting inactivity as evidence that an item should be demoted;
- a morning/afternoon/evening planning ritual the user must complete;
- exposing a detailed “why the algorithm changed your plan” dashboard.

I would also avoid automatically treating every new external signal as a reason to recurate Today. That would undermine the boundary from the earlier **Noticed** exploration: externally detected information is not automatically adopted attention.

The canon-level principle I’d propose is:

> **Today preserves orientation by default. It adapts when known reality materially changes the usefulness of the current path, and consequential unsolicited changes are proposed before they replace that path.**

I’m not generating a mockup this run because the existing **03 / 04 Today captures already make the placement fairly concrete**: the only proposed visual addition is a temporary, low-weight slip immediately above the existing Right now parchment when a genuine re-entry mismatch needs attention. The more important decision here is the trigger policy; designing a more elaborate surface would overstate the feature.
