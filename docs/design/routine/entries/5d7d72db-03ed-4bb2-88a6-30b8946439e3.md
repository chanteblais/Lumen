### CURRENT CANON

Coherence already treats **importance, urgency, user-expressed priority, and present-attention relevance as different things**. Today is allowed to adapt to capacity and immediate circumstances; Library ordering can be evidence of judgment; and the canon explicitly rejects collapsing all of this into a universal priority score. A Today-only choice also must not silently rewrite a durable priority. fileciteturn8file0L2-L2

The unresolved piece is Q11: how a statement like *“Practicum needs to come first this month”* should persist, expire, conflict with other commitments, and influence Lumi later without becoming another system the user has to maintain. fileciteturn9file0L2-L2

### OPEN QUESTION

How does Coherence remember **what the user says matters** without turning that meaning into `priority = 8`, permanent ordering, or repeated manual re-sorting?

The existing system can reorder Today and reason about due dates and capacity, but it does not yet have a first-class representation for scoped priority declarations. fileciteturn7file0L2-L2

### PROPOSAL — **Priority is a sentence, not a score**

When the user makes an explicit statement of priority, Lumi should preserve the *meaning of that statement* as a scoped declaration.

> **“Practicum comes before Coherence work this month.”**

Internally, Coherence can understand that as something closer to:

**Practicum → prefer over Coherence → for discretionary attention → through September → explicitly stated by user**

—not `Practicum = 92` and `Coherence = 71`.

That declaration would influence recommendations across spaces without mechanically controlling them. Tomorrow, Today might favour practicum work. In Library, Lumi might preserve the user's ordering. In conversation, if the user asks what to work on, Lumi has durable evidence instead of reconstructing the preference from recent behaviour.

Crucially, **short-term context would layer over it rather than overwrite it**.

If the user later says:

> “I really can't do school today.”

Coherence can treat that as **today's exclusion**, while still remembering that practicum matters deeply this month.

Likewise:

> “Actually, taxes need to take precedence until they're handled.”

doesn't require the user to reorganize every related task. It supersedes or narrows the earlier declaration where their scopes overlap.

I think the most important design rule is that priority declarations should usually have a **scope and a horizon**. Some horizons are temporal (*this week, this semester*); others are conditional (*until taxes are paid, while Mom is visiting, until this launch is over*). Explicit horizons expire quietly. Vague ones such as *“for now”* can remain active until contradicted or until Lumi has a real reason to suspect the context changed—without generating a recurring “review your priorities” chore.

This also gives Coherence a much better answer to **“Why are you suggesting this?”**

Lumi could explain:

> “You told me practicum was your main discretionary priority this month, and supervision is tomorrow. That's why I put this ahead of the website work.”

That is far more trustworthy than an opaque ranking algorithm.

There is a nice architectural consequence, too: this could be one of the **first richer concepts added to the shared model** without requiring the whole future ontology. A priority declaration only needs something like *subject, relationship/scope, horizon, source, status, and supersession*. That directly advances Q11 while respecting Q22's warning not to build the entire life-model architecture prematurely. fileciteturn9file0L2-L2

I wouldn't mock this one up yet. Its value is mostly behavioural: **Coherence remembers your priorities as contextual meaning, not as numbers.** The UI can remain very quiet until there is something worth inspecting or correcting.
